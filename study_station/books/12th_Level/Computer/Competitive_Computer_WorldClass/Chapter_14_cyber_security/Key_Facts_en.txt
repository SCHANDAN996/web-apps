1. **CIA Triad** — Confidentiality, Integrity, Availability form the core security objectives. Confidentiality prevents unauthorized access; Integrity ensures data accuracy; Availability guarantees timely access to authorized users.

2. **Threat, Vulnerability, Risk** — Threat = potential danger (e.g., hacker); Vulnerability = weakness (e.g., unpatched software); Risk = likelihood × impact of threat exploiting vulnerability.

3. **Malware Categories** — Virus (attaches to files, needs host), Worm (self-replicating, network-aware), Trojan (disguised as legitimate), Ransomware (encrypts data for ransom), Spyware (steals data silently), Adware (unwanted ads), Rootkit (hides deep in OS).

4. **Phishing Variants** — Email phishing (bulk deceptive emails), Spear phishing (targeted at specific person/org), Whaling (targets executives), Smishing (SMS), Vishing (voice call), Pharming (DNS hijack to fake site).

5. **Social Engineering** — Manipulates human psychology: pretexting (fabricated scenario), baiting (infected USB), tailgating (physical access), quid pro quo (service for info). Defense: verify identity, never share credentials.

6. **DoS vs DDoS** — DoS: single source floods target; DDoS: botnet (compromised devices) floods target. Common vectors: SYN flood, UDP flood, HTTP flood, amplification attacks (DNS, NTP).

7. **Man-in-the-Middle (MITM)** — Attacker intercepts/alters communication between two parties. Variants: ARP spoofing, DNS spoofing, HTTPS stripping, Wi-Fi eavesdropping. Defense: TLS/VPN, certificate pinning.

8. **SQL Injection (SQLi)** — Malicious SQL inserted via input fields to manipulate database. Types: In-band (error-based, union-based), Blind (boolean, time-based), Out-of-band. Defense: parameterized queries, input validation, WAF.

9. **Cross-Site Scripting (XSS)** — Injects malicious scripts into trusted websites. Stored (persistent in DB), Reflected (via URL), DOM-based (client-side). Defense: output encoding, CSP headers, HttpOnly cookies.

10. **Firewall Types** — Packet-filtering (stateless, header only), Stateful inspection (tracks connection state), Application-layer (proxy, inspects payload), Next-Gen (IPS, SSL inspection, identity awareness).

11. **IDS vs IPS** — IDS (Intrusion Detection System): monitors, alerts only. IPS (Intrusion Prevention System): monitors, blocks actively. Detection methods: signature-based (known patterns), anomaly-based (deviations from baseline).

12. **VPN (Virtual Private Network)** — Encrypted tunnel over public network. Protocols: IPsec (site-to-site, transport/tunnel mode), SSL/TLS (remote access), WireGuard (modern, lightweight). Split tunneling routes only corporate traffic via VPN.

13. **Symmetric Encryption** — Single key for encrypt/decrypt. Fast, suitable for bulk data. Algorithms: AES (128/192/256-bit, standard), ChaCha20 (mobile), DES/3DES (legacy, deprecated). Key distribution is challenge.

14. **Asymmetric Encryption** — Key pair: public (encrypt/verify), private (decrypt/sign). Slower, used for key exchange, digital signatures. Algorithms: RSA (2048/4096-bit), ECC (256-bit equivalent to RSA 3072), Diffie-Hellman (key agreement).

15. **Hashing** — One-way function, fixed-length output (digest). Properties: deterministic, avalanche effect, collision resistance. Algorithms: SHA-256 (standard), SHA-3, bcrypt/Argon2/PBKDF2 (password hashing with salt, slow by design). MD5/SHA-1 broken.

16. **Digital Signature** — Hash of message encrypted with sender's private key. Provides authenticity, integrity, non-repudiation. Verified with sender's public key. Used in code signing, certificates, blockchain.

17. **PKI (Public Key Infrastructure)** — Framework for digital certificates. Components: CA (issues/signs certs), RA (verifies identity), Certificate Repository, CRL/OCSP (revocation check). X.509 standard format.

18. **TLS/SSL** — Transport Layer Security (successor to SSL). Handshake: key exchange (RSA/ECDHE), authentication (certificate), symmetric session keys. Versions: TLS 1.2 (widely used), TLS 1.3 (faster, mandatory forward secrecy). HTTPS = HTTP over TLS.

19. **Authentication Factors** — Something you know (password/PIN), Something you have (OTP token, smart card, phone), Something you are (biometric), Somewhere you are (geolocation), Something you do (behavioral). MFA = 2+ distinct factors.

20. **Password Best Practices** — Minimum 12 chars, mixed case, numbers, symbols; unique per service; use password manager; enable MFA; avoid dictionary words, personal info, patterns. NIST guidelines: length > complexity, no forced rotation without compromise.

21. **Security Principles** — Least Privilege (minimum access needed), Defense in Depth (layered controls), Fail-Safe Defaults (deny by default), Separation of Duties (no single person controls critical task), Zero Trust (never trust, always verify).

22. **Indian IT Act 2000 (Amended 2008)** — Legal framework for cybercrime, e-commerce. Key sections: 43 (damage to computer), 66 (computer-related offenses), 66C (identity theft), 66D (cheating by personation), 67 (obscene content), 69 (govt interception powers), 72 (breach of confidentiality).

23. **CERT-In (Indian Computer Emergency Response Team)** — Nodal agency for cyber incidents. Functions: incident response, alerts/advisories, vulnerability coordination, security audits, awareness. Mandatory incident reporting within 6 hours (2022 directions). Operates Cyber Swachhta Kendra (botnet cleaning).

24. **RBI Cyber Security Framework (Banks)** — Mandates: board-approved policy, CISO, SOC, baseline controls (firewall, IDS/IPS, SIEM, DLP, encryption), third-party risk management, incident reporting (2-6 hours), annual audit, customer awareness.

25. **Security Hygiene Checklist** — OS/apps updated (auto-update), reputable antivirus/EDR, firewall enabled, regular offline backups (3-2-1 rule), MFA on critical accounts, phishing awareness, least-privilege accounts, disable unused services/ports, encrypt sensitive data at rest/in transit.
