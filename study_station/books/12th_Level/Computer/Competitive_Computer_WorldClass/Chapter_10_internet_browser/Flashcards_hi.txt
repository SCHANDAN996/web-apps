कार्ड 1
सामने: इंटरनेट क्या है?
पीछे: इंटरनेट विश्वभर के कंप्यूटर नेटवर्कों का एक वैश्विक नेटवर्क है जो TCP/IP प्रोटोकॉल सूट का उपयोग करके आपस में जुड़े होते हैं। यह विकेंद्रीकृत है — कोई एकल इकाई इसका स्वामित्व या नियंत्रण नहीं करती।
स्रोत: NCERT कक्षा 10 सूचना एवं संचार प्रौद्योगिकी (ICT)

कार्ड 2
सामने: वर्ल्ड वाइड वेब (WWW) और इंटरनेट में अंतर
पीछे: इंटरनेट = बुनियादी ढांचा (हार्डवेयर, केबल, राउटर, प्रोटोकॉल)। WWW = इंटरनेट पर चलने वाली एक सेवा जो हाइपरटेक्स्ट (HTML) और HTTP का उपयोग करके दस्तावेज़ों को जोड़ती है। WWW इंटरनेट का एक उपसमुच्चय है।
स्रोत: NCERT कक्षा 10 सूचना एवं संचार प्रौद्योगिकी (ICT)

कार्ड 3
सामने: URL के घटक
पीछे: प्रोटोकॉल://डोमेन:पोर्ट/पथ?क्वेरी#फ्रैगमेंट। उदाहरण: https://www.example.com:443/path/page?name=value#section। पोर्ट वैकल्पिक है (HTTP के लिए डिफ़ॉल्ट 80, HTTPS के लिए 443)।
स्रोत: RFC 3986 / Microsoft Learn

कार्ड 4
सामने: HTTP और HTTPS में अंतर
पीछे: HTTP (पोर्ट 80) सादे पाठ में डेटा भेजता है; HTTPS (पोर्ट 443) TLS/SSL एन्क्रिप्शन का उपयोग करता है। HTTPS सर्वर की पहचान प्रमाणित करता है और पारगमन में डेटा की अखंडता/गोपनीयता सुनिश्चित करता है। ब्राउज़र एड्रेस बार में पैडलॉक आइकन HTTPS दर्शाता है।
स्रोत: Microsoft Learn / CERT-In दिशानिर्देश

कार्ड 5
सामने: सामान्य शीर्ष-स्तरीय डोमेन (TLD) और उनका अर्थ
पीछे: .com (व्यावसायिक), .org (संगठन), .net (नेटवर्क), .edu (शैक्षणिक — मुख्यतः US), .gov (सरकार — मुख्यतः US), .in (भारत ccTLD), .mil (सैन्य)। ccTLD = देश कोड TLD (उदाहरण: .uk, .jp, .in)।
स्रोत: IANA रूट ज़ोन डेटाबेस

कार्ड 6
सामने: DNS क्या करता है?
पीछे: डोमेन नेम सिस्टम (DNS) मानव-पठनीय डोमेन नामों (example.com) को IP पतों (93.184.216.34) में अनुवादित करता है। पदानुक्रम: रूट सर्वर → TLD सर्वर → प्राधिकारी नेम सर्वर। रिज़ॉल्वर (ISP/सार्वजनिक DNS जैसे 8.8.8.8) उपयोगकर्ता की ओर से पुनरावर्ती रूप से क्वेरी करता है।
स्रोत: NCERT कक्षा 12 कंप्यूटर विज्ञान / RFC 1034

कार्ड 7
सामने: IPv4 बनाम IPv6 पता प्रारूप
पीछे: IPv4 = 32-बिट, डॉटेड-डेसिमल (192.168.1.1), ~4.3 अरब पते। IPv6 = 128-बिट, हेक्साडेसिमल कॉलन-अलग (2001:0db8:85a3::8a2e:0370:7334), विशाल पता स्थान। IPv6 में अंतर्निहित IPsec, कोई NAT आवश्यक नहीं।
स्रोत: NCERT कक्षा 12 कंप्यूटर विज्ञान / RFC 8200

कार्ड 8
सामने: वेब ब्राउज़र के मुख्य घटक
पीछे: (1) उपयोगकर्ता इंटरफ़ेस (एड्रेस बार, बटन, बुकमार्क), (2) ब्राउज़र इंजन (UI और रेंडरिंग इंजन के बीच पुल), (3) रेंडरिंग इंजन (HTML/CSS पार्स करता है, लेआउट बनाता है — Blink Chrome/Edge में, WebKit Safari में, Gecko Firefox में), (4) नेटवर्किंग (HTTP अनुरोध), (5) JavaScript इंजन (V8, SpiderMonkey, JavaScriptCore), (6) UI बैकएंड, (7) डेटा संग्रहण (कुकीज़, localStorage, IndexedDB)।
स्रोत: Microsoft Learn (Edge आर्किटेक्चर) / MDN Web Docs

कार्ड 9
सामने: ब्राउज़र रेंडरिंग पाइपलाइन (महत्वपूर्ण चरण)
पीछे: HTML पार्स → DOM ट्री → CSS पार्स → CSSOM ट्री → DOM + CSSOM = रेंडर ट्री → लेआउट (ज्यामिति गणना) → पेंट (पिक्सेल रैस्टराइज़) → कम्पोज़िट (लेयर्स संयोजन)। JavaScript DOM/CSSOM को संशोधित कर सकता है, जिससे पुनः लेआउट/पेंट ट्रिगर होता है।
स्रोत: MDN Web Docs / Chrome Developers

कार्ड 10
सामने: कुकीज़, sessionStorage, localStorage में अंतर
पीछे: कुकीज़: सर्वर (Set-Cookie हेडर) या क्लाइंट (JavaScript) द्वारा सेट, हर HTTP अनुरोध के साथ भेजी जाती हैं, समाप्ति तिथि, 4 KB सीमा। sessionStorage: टैब-विशिष्ट, टैब बंद होने पर साफ़, ~5 MB, सर्वर को नहीं भेजी जाती। localStorage: स्थायी, मूल-विशिष्ट, ~5 MB, सर्वर को नहीं भेजी जाती। तीनों समान-मूल नीति का पालन करते हैं।
स्रोत: MDN Web Docs / RFC 6265

कार्ड 11
सामने: ब्राउज़र कैश नियंत्रण हेडर
पीछे: Cache-Control: max-age=3600 (सेकंड में ताज़गी), no-cache (पुनः सत्यापन बाध्य), no-store (कोई संग्रहण नहीं), must-revalidate। ETag / Last-Modified सशर्त अनुरोध (304 Not Modified) सक्षम करते हैं। Expires (पुराना) निरपेक्ष तिथि देता है।
स्रोत: RFC 9111 / MDN Web Docs

कार्ड 12
सामने: सामान्य ब्राउज़र शॉर्टकट (Windows/Linux)
पीछे: Ctrl+T = नया टैब, Ctrl+W = टैब बंद, Ctrl+Shift+T = अंतिम बंद टैब फिर से खोलें, Ctrl+Tab / Ctrl+Shift+Tab = अगला/पिछला टैब, Ctrl+L / Alt+D = एड्रेस बार फोकस, Ctrl+R / F5 = रीलोड, Ctrl+Shift+R = हार्ड रीलोड (कैश बायपास), Ctrl++ / Ctrl+- = ज़ूम इन/आउट, Ctrl+0 = डिफ़ॉल्ट ज़ूम, Ctrl+H = इतिहास, Ctrl+J = डाउनलोड, F11 = पूर्ण स्क्रीन टॉगल।
स्रोत: Microsoft Support (Edge) / Chrome शॉर्टकट दस्तावेज़

कार्ड 13
सामने: खोज इंजन कैसे काम करता है (तीन चरण)
पीछे: (1) क्रॉलिंग: बॉट्स (Googlebot) लिंक का अनुसरण करके पृष्ठ खोजते हैं। (2) इंडेक्सिंग: सामग्री पार्स, विश्लेषित, और उल्टे इंडेक्स में संग्रहीत। (3) रैंकिंग: एल्गोरिदम प्रासंगिकता, गुणवत्ता, उपयोगकर्ता संदर्भ का मूल्यांकन करते हैं; परिणाम SERP पर लौटाए जाते हैं। robots.txt क्रॉलिंग नियंत्रित करता है; noindex इंडेक्सिंग रोकता है।
स्रोत: Google Search Central दस्तावेज़ीकरण

कार्ड 14
सामने: सामान्य माइम प्रकार (MIME types)
पीछे: text/html, text/css, application/javascript, application/json, image/png, image/jpeg, image/webp, application/pdf, video/mp4, audio/mpeg, multipart/form-data। ब्राउज़र Content-Type हेडर के आधार पर हैंडलिंग तय करता है; गलत MIME प्रकार सुरक्षा जोखिम (MIME स्निफिंग) पैदा कर सकता है।
स्रोत: IANA मीडिया प्रकार रजिस्ट्री / MDN Web Docs

कार्ड 15
सामने: CORS (क्रॉस-ओरिजिन रिसोर्स शेयरिंग) क्या है?
पीछे: ब्राउज़र सुरक्षा तंत्र जो एक मूल (डोमेन, प्रोटोकॉल, पोर्ट) के वेब पृष्ठ को दूसरे मूल से संसाधनों का अनुरोध करने की अनुमति देता है यदि सर्वर अनुमति हेडर (Access-Control-Allow-Origin, Allow-Methods, Allow-Headers, Allow-Credentials) के साथ प्रतिक्रिया देता है। प्रीफ्लाइट OPTIONS अनुरोध गैर-सरल अनुरोधों के लिए जांच करता है।
स्रोत: MDN Web Docs / W3C CORS विनिर्देश

कार्ड 16
सामने: CSP (कंटेंट सिक्योरिटी पॉलिसी) का उद्देश्य
पीछे: HTTP हेडर (Content-Security-Policy) जो घोषित करता है कि कौन से डायनामिक संसाधन लोड/निष्पादित करने की अनुमति है (स्क्रिप्ट, स्टाइल, फॉन्ट, फ्रेम, कनेक्ट)। XSS और डेटा इंजेक्शन हमलों को कम करता है। उदाहरण: script-src 'self' https://trusted.cdn.com; object-src 'none'।
स्रोत: MDN Web Docs / W3C CSP स्तर 3

कार्ड 17
सामने: वेब एक्सेसिबिलिटी मूल बातें (WCAG सिद्धांत)
पीछे: POUR: Perceivable (वैकल्पिक पाठ, कैप्शन), Operable (कीबोर्ड नेविगेशन, कोई जब्ती ट्रिगर नहीं), Understandable (पठनीय पाठ, अनुमानित UI), Robust (मान्य HTML, ARIA भूमिकाएँ)। सेमांटिक HTML (header, nav, main, article, aside, footer) स्क्रीन रीडर्स की सहायता करता है।
स्रोत: W3C WCAG 2.1 / भारत सरकार GIGW दिशानिर्देश

कार्ड 18
सामने: प्रगतिशील वेब ऐप (PWA) की मुख्य विशेषताएं
पीछे: (1) सेवा कार्यकर्ता (ऑफ़लाइन कैशिंग, पुश सूचनाएं, पृष्ठभूमि सिंक), (2) वेब ऐप मैनिफेस्ट (नाम, आइकन, प्रारंभ URL, प्रदर्शन मोड), (3) HTTPS अनिवार्य, (4) उत्तरदायी डिज़ाइन, (5) ऐप-जैसा अनुभव (होम स्क्रीन पर इंस्टॉल करने योग्य, पूर्ण-स्क्रीन)। ब्राउज़र समर्थन: Chrome, Edge, Firefox, Safari (आंशिक)।
स्रोत: MDN Web Docs / Google Developers (Web Fundamentals)
