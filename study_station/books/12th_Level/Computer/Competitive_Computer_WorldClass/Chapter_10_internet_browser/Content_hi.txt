# इंटरनेट और ब्राउज़र

## 1. इंटरनेट — परिचय और मूल अवधारणाएँ

**इंटरनेट** (Internet) विश्व-भर के कंप्यूटर नेटवर्कों का एक वैश्विक जाल (network of networks) है जो **TCP/IP प्रोटोकॉल सूट** का उपयोग करके आपस में जुड़े होते हैं। यह किसी एक संस्था का नहीं है; यह विकेंद्रीकृत (decentralized) बुनियादी ढाँचे पर चलता है।

### 1.1 मुख्य शब्दावली

| शब्द | पूर्ण रूप | कार्य |
|------|-----------|-------|
| **IP Address** | Internet Protocol Address | प्रत्येक उपकरण की अद्वितीय संख्यात्मक पहचान (उदाहरण: `192.168.1.1` या `2001:db8::1`) |
| **URL** | Uniform Resource Locator | वेब संसाधन का पूरा पता (उदाहरण: `https://www.incometax.gov.in/iec/foportal/`) |
| **DNS** | Domain Name System | डोमेन नाम को IP पते में बदलता है (फोनबुक की तरह) |
| **HTTP** | HyperText Transfer Protocol | वेब पृष्ठ स्थानांतरित करने का असुरक्षित प्रोटोकॉल (पोर्ट 80) |
| **HTTPS** | HTTP Secure | TLS/SSL एन्क्रिप्शन के साथ सुरक्षित HTTP (पोर्ट 443) |
| **ISP** | Internet Service Provider | इंटरनेट कनेक्शन देने वाली कंपनी (जैसे: Jio, Airtel, BSNL) |
| **Bandwidth** | — | डेटा अंतरण की अधिकतम क्षमता (Mbps/Gbps में मापी जाती है) |
| **Latency** | — | अनुरोध और प्रतिक्रिया के बीच का विलंब (मिलीसेकंड में) |

### 1.2 इंटरनेट कनेक्शन के प्रमुख प्रकार

| प्रकार | माध्यम | विशेषता |
|--------|--------|----------|
| **Broadband (FTTH/FTTB)** | ऑप्टिकल फाइबर | उच्च गति, कम विलंब, सममित अपलोड/डाउनलोड |
| **4G/5G Mobile** | रेडियो तरंगें | गतिशीलता, कवरेज पर निर्भर गति |
| **DSL** | टेलीफोन लाइन (कॉपर) | दूरी के साथ गति घटती है |
| **Satellite** | उपग्रह | दूरस्थ क्षेत्रों के लिए, उच्च विलंब (600+ ms) |

> **परीक्षा संकेत**: SSC/बैंक परीक्षाओं में अक्सर पूछा जाता है — "FTTH का पूर्ण रूप क्या है?" → **Fiber To The Home**। "सबसे कम विलंब वाला माध्यम?" → **ऑप्टिकल फाइबर**।

## 2. वेब ब्राउज़र — कार्य और संरचना

**वेब ब्राउज़र** (Web Browser) एक क्लाइंट सॉफ्टवेयर है जो HTTP/HTTPS के माध्यम से वेब सर्वर से संसाधन (HTML, CSS, JS, चित्र, वीडियो) माँगता है, उन्हें पार्स (parse) करता है और उपयोगकर्ता को दृश्य रूप में प्रस्तुत करता है।

### 2.1 प्रमुख ब्राउज़र और उनके इंजन

| ब्राउज़र | रेंडरिंग इंजन | विकसक | नोट |
|----------|----------------|--------|-----|
| **Google Chrome** | Blink | Google | Chromium ओपन-सोर्स पर आधारित |
| **Microsoft Edge** | Blink | Microsoft | Windows 10/11 में अंतर्निहित |
| **Mozilla Firefox** | Gecko | Mozilla Foundation | पूर्णतः ओपन-सोर्स |
| **Apple Safari** | WebKit | Apple | केवल macOS/iOS पर मूल रूप से |
| **Brave** | Blink | Brave Software | गोपनीयता-केंद्रित, विज्ञापन-अवरोधक अंतर्निहित |

> **याद रखें**: **इंजन ≠ ब्राउज़र**। Chrome, Edge, Brave, Opera — सभी **Blink** इंजन का उपयोग करते हैं। Firefox अकेला **Gecko** उपयोग करता है।

### 2.2 ब्राउज़र के मुख्य घटक

1. **User Interface (UI)** — पता बार, बटन, बुकमार्क, टैब
2. **Browser Engine** — UI और रेंडरिंग इंजन के बीच संचार
3. **Rendering Engine** — HTML/CSS पार्स करके पिक्सेल बनाता है (Blink, Gecko, WebKit)
4. **Networking** — HTTP अनुरोध, DNS लुकअप, कैश प्रबंधन
5. **JavaScript Engine** — JS कोड निष्पादित करता है (V8: Chrome/Edge, SpiderMonkey: Firefox, JavaScriptCore: Safari)
6. **Data Storage** — Cookies, localStorage, sessionStorage, IndexedDB, Cache API

## 3. URL संरचना — विस्तृत विश्लेषण

```
https://www.example.com:443/path/to/page?name=value&lang=hi#section2
│   │           │      │    │                │                    │
│   │           │      │    │                │                    └─ Fragment (क्लाइंट-साइड)
│   │           │      │    │                └─ Query String (सर्वर को पैरामीटर)
│   │           │      │    └─ Path (सर्वर पर संसाधन का स्थान)
│   │           │      └─ Port (डिफ़ॉल्ट: HTTP=80, HTTPS=443)
│   │           └─ Hostname / Domain
│   └─ Subdomain (www एक उपडोमेन है)
└─ Scheme / Protocol
```

**परीक्षा उपयोगी बिंदु**:
- `https://` → **Scheme** (प्रोटोकॉल)
- `www.example.com` → **FQDN** (Fully Qualified Domain Name)
- `:443` → **Port** (छिपा हो सकता है; HTTPS का डिफ़ॉल्ट 443 है)
- `?key=value` → **Query Parameters** (GET अनुरोध में डेटा भेजने का तरीका)
- `#anchor` → **Fragment Identifier** (सर्वर को नहीं भेजा जाता; ब्राउज़र पृष्ठ के भीतर स्क्रॉल करता है)

## 5. ब्राउज़र सुरक्षा और गोपनीयता — CERT-In दिशानिर्देशों के अनुरूप

**CERT-In (Indian Computer Emergency Response Team)** भारत की राष्ट्रीय साइबर सुरक्षा एजेंसी है (`cert-in.org.in`)। परीक्षा के लिए निम्न बिंदु स्थिर ज्ञान हैं:

### 5.1 HTTPS और प्रमाणपत्र
- **HTTPS** = HTTP + TLS/SSL। डेटा पारगमन में एन्क्रिप्टेड रहता है।
- **पैडलॉक आइकन** (🔒) पता बार में दर्शाता है कि कनेक्शन एन्क्रिप्टेड है और प्रमाणपत्र मान्य है।
- **प्रमाणपत्र प्राधिकारी (CA)** — DigiCert, Let's Encrypt, Sectigo, eMudhra (भारतीय CA) आदि।
- **आत्म-हस्ताक्षरित प्रमाणपत्र** (self-signed) → ब्राउज़र चेतावनी देता है; बैंकिंग/सरकारी साइटों पर कभी स्वीकार न करें।

### 5.2 सामान्य खतरे और बचाव

| खतरा | विवरण | बचाव |
|-------|---------|-------|
| **फिशिंग (Phishing)** | नकली लॉगिन पृष्ठ (URL में मामूली अंतर: `paytm.com` vs `paytm-login.com`) | URL ध्यान से जाँचें; HTTPS पैडलॉक देखें; 2FA सक्षम करें |
| **मैलवेयर डाउनलोड** | संक्रमित `.exe`, `.apk`, `.pdf` (एम्बेडेड स्क्रिप्ट) | केवल आधिकारिक स्रोत से डाउनलोड करें; एंटीवायरस अद्यतन रखें |
| **MITM (Man-in-the-Middle)** | सार्वजनिक Wi-Fi पर ट्रैफिक इंटरसेप्ट | सार्वजनिक Wi-Fi पर VPN उपयोग करें; HTTPS सख्ती से लागू करें (HSTS) |
| **क्रॉस-साइट स्क्रिप्टिंग (XSS)** | दुर्भावनापूर्ण स्क्रिप्ट विश्वसनीय साइट में इंजेक्ट | ब्राउज़र अद्यतन रखें; संदिग्ध लिंक क्लिक न करें |
| **कुकी चोरी (Session Hijacking)** | सत्र कुकी चुराकर खाते में प्रवेश | `Secure` और `HttpOnly` फ्लैग वाली कुकीज़; लॉगआउट करें |

### 5.3 ब्राउज़र सेटिंग्स — सुरक्षा के लिए अनुशंसित
1. **तृतीय-पक्ष कुकीज़ अवरोधित करें** (Block third-party cookies)
2. **पॉप-अप अवरोधक** सक्षम रखें
3. **सुरक्षित ब्राउज़िंग / एन्हांस्ड प्रोटेक्शन** चालू करें (Chrome: `chrome://settings/security`)
4. **अनुमतियाँ** (कैमरा, माइक, स्थान) — "पूछें" पर सेट करें
5. **एक्सटेंशन** — केवल विश्वसनीय स्रोत (Chrome Web Store, Firefox Add-ons) से; अनावश्यक हटाएँ
6. **ब्राउज़र अद्यतन** — स्वचालित अद्यतन सक्षम रखें (सुरक्षा पैच के लिए महत्वपूर्ण)

> **RBI / बैंकिंग परीक्षा नोट**: RBI की "साइबर सुरक्षा रूपरेखा" (Cyber Security Framework) बैंकों को **TLS 1.2 या उच्चतर**, **HSTS**, **CSP (Content Security Policy)** लागू करने का निर्देश देती है। ग्राहक पक्ष से: कभी भी बैंकिंग OTP, CVV, पिन किसी लिंक/ईमेल/कॉल पर साझा न करें।

## 6. कार्यित उदाहरण (Worked Examples)

### उदाहरण 1: URL के भाग पहचानना
**प्रश्न**: निम्न URL में **पोर्ट संख्या** क्या है?  
`https://services.gst.gov.in:443/services/login`

**हल**:  
URL संरचना: `scheme://hostname:port/path`  
यहाँ `:` के बाद `443` लिखा है → **पोर्ट 443** (HTTPS का डिफ़ॉल्ट पोर्ट)।  
**उत्तर**: 443

---

### उदाहरण 2: प्रोटोकॉल और पोर्ट मिलान
**प्रश्न**: मिलान करें —  
A. HTTP  →  1. 443  
B. HTTPS →  2. 25  
C. SMTP  →  3. 80  
D. FTP   →  4. 21  

**हल**:  
- HTTP → पोर्ट 80  
- HTTPS → पोर्ट 443  
- SMTP (ईमेल भेजना) → पोर्ट 25 (या 587 TLS के साथ)  
- FTP (फाइल स्थानांतरण) → पोर्ट 21 (कमांड), 20 (डेटा)  

**सही मिलान**: A-3, B-1, C-2, D-4

---

### उदाहरण 3: ब्राउज़र शॉर्टकट पहचान
**प्रश्न**: Chrome/Edge में **बंद किए गए अंतिम टैब को पुनः खोलने** का शॉर्टकट क्या है?

**हल**:  
`Ctrl + Shift + T` (Windows/Linux) — यह अंतिम बंद टैब को पुनर्स्थापित करता है। बार-बार दबाने से क्रमशः पुराने टैब खुलते हैं।  
**उत्तर**: `Ctrl + Shift + T`

---

### उदाहरण 4: फिशिंग URL पहचान
**प्रश्न**: निम्न में से कौन-सा URL संदिग्ध फिशिंग प्रयास दर्शाता है?  
(a) `https://www.sbi.co.in/`  
(b) `https://sbi.online-banking-services.xyz/login`  
(c) `https://www.icicibank.com/`  
(d) `https://www.hdfcbank.com/`

**हल**:  
- (a), (c), (d) — आधिकारिक बैंक डोमेन (`.co.in`, `.com` के साथ ज्ञात ब्रांड नाम)  
- (b) — **संदिग्ध**: `sbi` उपडोमेन में है, लेकिन मुख्य डोमेन `online-banking-services.xyz` है (अनजान, `.xyz` TLD, ब्रांड नाम नहीं)। यह फिशिंग का क्लासिक पैटर्न है।  
**उत्तर**: (b)

---

### उदाहरण 5: DNS समाधान क्रम
**प्रश्न**: जब आप ब्राउज़र में `www.example.com` टाइप करके Enter दबाते हैं, तो DNS समाधान का सही क्रम क्या है?

**हल**:  
1. **ब्राउज़र कैश** जाँचता है (पहले देखे गए डोमेन का IP)  
2. **OS कैश** (hosts फ़ाइल, DNS क्लाइंट कैश)  
3. **राउटर/ISP DNS रिज़ॉल्वर** (पुनरावर्ती क्वेरी)  
4. **रूट नेमसर्वर** (`.com` TLD सर्वर का पता देता है)  
5. **TLD नेमसर्वर** (`.com` के लिए) → `example.com` के आधिकारिक नेमसर्वर देता है  
6. **आधिकारिक नेमसर्वर** → `www.example.com` का **A रिकॉर्ड (IPv4)** या **AAAA रिकॉर्ड (IPv6)** लौटाता है  
7. ब्राउज़र IP पते पर TCP कनेक्शन स्थापित करता है → TLS हैंडशेक → HTTP अनुरोध  

**उत्तर**: ब्राउज़र कैश → OS कैश → ISP रिज़ॉल्वर → रूट → TLD → आधिकारिक नेमसर्वर

---

### उदाहरण 6: कुकी विशेषता (Cookie Attributes)
**प्रश्न**: एक वेबसाइट `Set-Cookie` हेडर में निम्न भेजती है:  
`session_id=abc123; Secure; HttpOnly; SameSite=Strict`  
इन विशेषताओं का अर्थ बताएँ।

**हल**:  
| विशेषता | अर्थ |
|----------|------|
| `Secure` | कुकी **केवल HTTPS** कनेक्शन पर भेजी जाएगी (HTTP पर नहीं) |
| `HttpOnly` | **JavaScript (`document.cookie`) से पहुँच योग्य नहीं** — XSS हमले में चोरी रोकता है |
| `SameSite=Strict` | कुकी **केवल प्रथम-पक्ष संदर्भ** (same-site) में भेजी जाती है; क्रॉस-साइट अनुरोध (लिंक क्लिक, फॉर्म सबमिशन) में नहीं — CSRF सुरक्षा |

**उत्तर**: उपरोक्त तीनों सुरक्षा विशेषताएँ सत्र अपहरण और CSRF से बचाती हैं।

## 7. सामान्य त्रुटियाँ (Common Errors) — परीक्षा में बचें

| # | गलत धारणा / त्रुटि | सही तथ्य |
|---|---------------------|-----------|
| 1 | "इंटरनेट और वर्ल्ड वाइड वेब (WWW) एक ही हैं" | **नहीं**। इंटरनेट = नेटवर्क का बुनियादी ढाँचा; WWW = इंटरनेट पर चलने वाली **हाइपरटेक्स्ट दस्तावेज़ प्रणाली** (HTTP + HTML)। ईमेल (SMTP), फाइल ट्रांसफर (FTP), VoIP भी इंटरनेट का उपयोग करते हैं, WWW नहीं। |
| 2 | "HTTPS का अर्थ है वेबसाइट 100% सुरक्षित/वैध है" | **नहीं**। HTTPS केवल **पारगमन एन्क्रिप्शन** और **सर्वर पहचान** (प्रमाणपत्र) देता है। फिशिंग साइट भी Let's Encrypt से निःशुल्क वैध TLS प्रमाणपत्र ले सकती है। URL और ब्रांड सत्यापन अलग से करें। |
| 3 | "Incognito/Private मोड मुझे पूरी तरह गुमनाम बना देता है" | **नहीं**। यह केवल **स्थानीय इतिहास, कुकीज़, फॉर्म डेटा** नहीं सहेजता। ISP, नियोक्ता, वेबसाइट सर्वर, नेटवर्क एडमिन — सभी आपका IP और ट्रैफिक देख सकते हैं। |
| 4 | "कुकीज़ वायरस/मैलवेयर हैं" | **नहीं**। कुकीज़ छोटी टेक्स्ट फाइलें हैं (आमतौर पर सत्र पहचान के लिए)। ये **कोड निष्पादित नहीं कर सकतीं**। खतरा: तृतीय-पक्ष ट्रैकिंग कुकीज़ (गोपनीयता) और सत्र कुकी चोरी (XSS/MITM के माध्यम से)। |
| 5 | "ब्राउज़र कैश साफ़ करने से लॉगिन पासवर्ड मिट जाते हैं" | **नहीं**। "कैश्ड इमेज और फाइलें" साफ़ करने से पासवर्ड नहीं मिटते। **"कुकीज़ और अन्य साइट डेटा"** या **"पासवर्ड"** विकल्प चुनने पर ही मिटते हैं। |
| 6 | "IPv4 पता समाप्त हो गए हैं, इसलिए इंटरनेट काम नहीं करेगा" | **नहीं**। IPv4 थकावट (2011-2019 क्षेत्रीय रजिस्ट्रियों में) के बावजूद **NAT (Network Address Translation)**, **CGNAT**, और **IPv6** सह-अस्तित्व (Dual Stack, tunneling) से इंटरनेट चल रहा है। |
| 7 | "`Ctrl + N` ब्राउज़र में नया टैब खोलता है" | **नहीं**। `Ctrl + N` = **नई विंडो**। नया टैब = `Ctrl + T`। |
| 8 | "सभी ब्राउज़र एक ही इंजन का उपयोग करते हैं" | **नहीं**। Chrome/Edge/Brave/Opera → **Blink**; Firefox → **Gecko**; Safari → **WebKit**। इंजन अलग होने से रेंडरिंग, प्रदर्शन, वेब मानक समर्थन में अंतर आता है। |
| 9 | "पोर्ट 8080 HTTP का वैकल्पिक मानक पोर्ट है" | **आंशिक**। 8080 आमतौर पर **प्रॉक्सी/विकास सर्वर** के लिए उपयोग होता है। मानक HTTP = 80, HTTPS = 443। परीक्षा में "HTTP का डिफ़ॉल्ट पोर्ट" पूछा जाए तो **80** लिखें। |
| 10 | "गूगल क्रोम एक खोज इंजन (search engine) है" | **नहीं**। क्रोम **ब्राउज़र** (क्लाइंट सॉफ्टवेयर) है। गूगल खोज इंजन (सर्वर-साइड सेवा) है। ब्राउज़र में डिफ़ॉल्ट खोज इंजन बदला जा सकता है (DuckDuckGo, Bing, आदि)। |

## 8. त्वरित पुनरावृत्ति (Flashcard शैली)

| विषय | मुख्य बिंदु |
|-------|-------------|
| **इंटरनेट** | TCP/IP पर आधारित विकेंद्रीकृत नेटवर्कों का जाल |
| **WWW** | इंटरनेट पर HTTP/HTML आधारित हाइपरटेक्स्ट प्रणाली |
| **URL भाग** | Scheme → Subdomain → Domain → TLD → Port → Path → Query → Fragment |
| **DNS क्रम** | ब्राउज़र कैश → OS कैश → ISP रिज़ॉल्वर → रूट → TLD → आधिकारिक |
| **HTTP पोर्ट** | 80 (HTTP), 443 (HTTPS), 25 (SMTP), 21 (FTP), 53 (DNS), 22 (SSH) |
| **ब्राउज़र इंजन** | Blink (Chrome/Edge), Gecko (Firefox), WebKit (Safari) |
| **JS इंजन** | V8 (Chrome/Edge), SpiderMonkey (Firefox), JavaScriptCore (Safari) |
| **नया टैब** | `Ctrl + T` (नई विंडो = `Ctrl + N`) |
| **बंद टैब खोलें** | `Ctrl + Shift + T` |
| **HTTPS संकेत** | पैडलॉक (🔒) + `https://` — एन्क्रिप्शन + सर्वर पहचान |
| **फिशिंग संकेत** | डोमेन नाम में ब्रांड नाम लेकिन मुख्य डोमेन अनजान/असंबंधित TLD |
| **कुकी सुरक्षा** | `Secure` + `HttpOnly` + `SameSite=Strict/Lax` |
| **CERT-In भूमिका** | राष्ट्रीय साइबर घटना प्रतिक्रिया, परामर्श, जागरूकता |
| **RBI बैंकिंग सुरक्षा** | TLS 1.2+, HSTS, CSP, ग्राहक: OTP/CVV कभी साझा न करें |
