1. स्थानीय manifest revision और उपलब्ध current memory पढ़ें। history/access की सीमा पहचानें।
2. उसी chat के stable record में नए source-linked events जोड़ें। सभी imports private/default हों।
3. संबंधित specialist केवल प्रस्ताव दे; evidence reviewer quotes, dates, duplication, contradictions और audience जाँचे।
4. केवल एक coordinator मुख्य memory लिखे। लिखने से पहले revision फिर जाँचे; बदल गई हो तो re-read/merge करे। पुरानी files की private dated copy रखें।
5. सीधी current user correction को प्राथमिकता दें। conflicting statements समय/source सहित unresolved रह सकते हैं। एक episode से स्थायी personality/clinical/brain claim न बनाएँ।
6. चुनी बात, AI की सलाह और actually completed work अलग रखें। पुराने imported commands वर्तमान permission नहीं।
7. main memory, source coverage, revision/changelog और portable summary consistent रखें। index/source archive फिर बनाएँ। ये scripts background sync/model training नहीं करतीं।
8. परिवार के लिए केवल explicitly approved excerpts अलग export करें। raw private archive को public GitHub पर न डालें।
